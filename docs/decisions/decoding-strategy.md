# DEC-001 — Default decoding: candidate scoring (not free generation)

**Status:** ✅ Decided — recorded in PRD v1.1.0 §3.4 ("decisão registrada")
**Date:** 2026-10-03 (recorded in this workspace; decided as part of PRD v1.1.0)
**Workspace ID:** WS-AD-003 (`.specs/project/STATE.md`)
**PRD traceability:** §3.4, §5.1, §5.4 → KPIs `JSON ok` (§2) → acceptance §7.1

## Context

The SLM must answer wire requests containing `choice`, `score` and `noul` questions, and the response schema is frozen (ADR-0001). Two families of answer construction were possible: **free generation** of the response, or **scoring of candidates** computed from logits. The repository already has evidence that small models fail the first option: B-10 measured `ling-tiny` at `JSON ok` 0.889/0.917 and **46 seconds per attempt** with 52 options; the contract allows up to 255 `options`.

## Decision

**The default mode builds answers by scoring candidates — no free generation.**

| Primitive | Method | Output guarantees |
| --- | --- | --- |
| `choice` | Length-normalized logprob of each `criteria` label as continuation of the same prefix (shared-prefix batch) → `softmax(logprobs)` | `probabilities` sum to **1.0 by construction**; `confidence` = modal label mass |
| `noul` | `noul = sigmoid(ℓ(true) − ℓ(false))` over `criteria.true/false` | **float 0..1** — the wire has no `ptrue` and no `"false"` string |
| `score` | Softmax over level indices | `probabilities` per index; `score = Σ i·pᵢ` (expected value, as in `protocol.md`); `legend` mirrored from the request; `confidence` = modal index mass |

**Golden rule:** `confidence` and `probabilities` are **never text generated by the model** — they come from logits and the temperature fit of PRD §3.5.

## Alternatives

| Alternative | Verdict | Why |
| --- | --- | --- |
| Free generation of the JSON response | ❌ Rejected (default) | B-10: contract failures (≤ 0.889) and 46 s/52-option cost; compliance would depend on prompt luck |
| Generation with **constrained decoding** of the `answers` values | ⚙️ **Experimental opt-in, Phase 4** | Only mode that may emit an internal scratchpad (discarded by the runtime); needs grammar (§5.4) + rescoring for probabilities; degrades with many options |
| Scoring via an external LLM (current candidates) | ❌ Out of product scope | 1.2–6.8 s p50, 4.8–5.5 GB VRAM — exactly what this PRD replaces (§1.3) |

## Consequences

- ✅ `JSON ok` = 1.000 is achievable **by construction** (§7.1).
- ✅ Stable cost regardless of option count (up to 255) and ~0 generated tokens in the default path (`usage.output_tokens = 0`) — supports p50 < 20 ms and the FP8@L4 stretch (§4.5).
- ✅ Native probability distributions for the wire invariants; coherent with the project's "single forward pass" identity (peer: `pngwn/system-one-qwen3.5-4b-scorer`).
- ⚠️ No free-form reasoning by default — hard-slice gains from reasoning require the experimental mode (Phase 4).
- ⚠️ SFT targets must be rendered as scoring pairs (Phase 1 renderer, §3.4).
